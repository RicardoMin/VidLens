# 从证据到技术讲解

这份指南用于组织已经读过的材料。视频里没有的经历、实验结果和动机，不能靠流畅文风补出来。示例中的数字是教学演算，不代表任何视频的原始数据。

## 先让读者看见过程

从读者眼前的问题进入过程。选择一个贯穿解释的输入，让后面的概念逐一回答这个输入遇到的问题。解释手写数字分类，可以先沿一张“7”走到输出；需要借“9”的圆圈讲特征时，说清为什么换例子。介绍新术语时交代它在这一步做什么，而不是先铺一页名词。按材料需要组织，不必每次套用“背景—原理—优缺点”标题。

输入：用户问“KV cache 为什么能让生成变快？”视频已展示逐 token 解码。

较好的讲解：

> 假设前三个 token 的 K 和 V 已经缓存，第四个 token 也刚刚采样出来。现在把第四个 token 送入模型，预测第五个。这一轮只计算第四个 token 的 Q、K、V，把新的 K、V 追加到缓存，再让它的 Q 与这四个位置的 K 做注意力计算，并读取对应的 V。这样省掉了前三个 token 的 K、V 等重复计算；随着上下文增长，读取缓存和计算 attention 的工作仍会增加。

它给出了已有状态、新增工作和仍然存在的开销。“缓存提高效率”“避免重复计算”只有在这些对象明确以后才有用。模型结构不同可能改变实现细节；根据视频实际实现补充，不预先堆一段泛化免责声明。

## 让原图承担一部分解释

已经看过的关键图可以直接交给读者。选择能回答当前问题的画面：一个符号的定义、某一步新添的数据、实验结果的变化。标题页、黑场和动画过渡通常不值得占一个讲解位置。图中细节不清楚时先取清晰帧或裁剪。

图前指出要看哪里，图注说明可见事实，图后连接它的含义。例如讲 KV Cache 时：

> 看右边紫色的 K：上面三行属于“床、前、明”，下面单独的一行属于刚送进来的“月”。我们把这一行接到缓存后面，就有了本轮所需的四行 K。V 做同样的追加，当前“月”的 Q 再读取这四个位置。

这里应配确实显示这些行的原视频截图，图注可以是“紫色 K 的历史三行与新增的‘月’分开显示（08:40）”，并链接到原片。不要用一张没有这些细节的网络总览图代替。Markdown 可嵌入本地图片；需要可分享的离线文件时，使用 [HTML helper](interactive.md) 的 `image` 字段。

原图与自绘示意分工不同：原图让读者核对公式、标注和结果；示意图把跨章关系连起来。两者不用重复表达整段文字。添加箭头或重新画图时，不把推导出的关系说成原视频已经画出的内容。

图注描述这一帧实际呈现的状态。比如 K 仍按“三行加一行”分开放置，就写“上面三行复用，下面一行追加”；算法上已得到四个位置，并不意味着画面已把四行拼在一起。需要解释动画的前后变化时，配对应的两帧。

读取密集的性能报告时，先按[图表事实核对流程](fact-checking.md)核对字段名、数值、单位、统计口径及推导。分别核对相邻的命中率、吞吐率和忙碌指标；总览的聚合值也不能直接代替某条管线的测量值。某个末位看不清，就保留可支持的精度，或用清楚的那一项演算；不要把旁边相似的数字补进来。核对记录不占用正文，让图注指出字段，让段落解释它为什么影响下一步判断。

## 用小输入检查每一步

输入：用户看不懂代码 `softmax(scores / temperature)`。

教学演算：

> 先只看两个分数 `[2, 1]`。温度为 1 时，指数化并归一化得到约 `[0.731, 0.269]`；温度为 0.5 时，先变成 `[4, 2]`，再得到约 `[0.881, 0.119]`。两个选项的顺序没变，但较高分选项占的概率更大了。温度改变的是分布的尖锐程度，这一步本身还没有选出 token。

给出输入、变换、输出和输出的含义。计算示例可用 Python 核对；从画面引用具体数组或公式时，先核对实际图像。若视频只给出直觉，明确把演算称为“用一个两项例子来看”。

长讲解可以在关键转折留下一个可推理的小问题，例如“隐藏层换成 ReLU、输出层仍用 sigmoid，哪一层可能超过 1？”接着沿刚才的计算解释答案。它检验的是概念能否用于变式，不是让读者背总结。只有用户想练习时，才停下来等待作答。

English input: “Why does the diagram reuse the old keys?”

Useful output:

> At this decoding step, the previous tokens have already produced their keys and values. The new token supplies a new query, which attends to those stored keys and uses the corresponding values. Reusing them saves recomputation of the prefix. The attention still reads the growing cache, so caching does not make each decoding step independent of context length.

这里直接说清对象与因果，不先写 “This is not just an optimization; it is a paradigm shift.” 这种没有增加信息的句子。

## 把章节接起来

读完后找出跨章依赖：前一章提出的限制，下一章怎样解决；某个实验是在检验哪一个机制；代码中的哪个对象对应图里的哪条边。用这些关系决定讲述顺序。

例如材料先讲带宽限制、再讲分块搬运、最后比较延迟，可以从“一次请求的数据如何移动”串起来，解释分块怎样改变等待过程，再读实验指标。不要把一次低延迟样本写成所有硬件上的性能保证。

必要时给出简短角色表，避免在名词堆里迷路：

| 对象 | 此处承担的工作 | 进入／离开它的数据 |
|---|---|---|
| query | 决定当前 token 关注哪里 | 当前 token 的表示 → 匹配分数 |
| key | 提供用于匹配的位置特征 | 历史 token 的表示 → 与 query 匹配 |
| value | 提供按权重汇总的内容 | 历史 token 的表示 → attention 输出 |

## 分清讲解和核对记录

读者需要跟上内容的变化。字幕来自哪里、读完哪些分页、核对过哪些帧、运行过哪些测试，保留在工作记录或用户要求的评审中；正文用贴近相应内容的来源链接和图注完成归属。交付文件若有影响使用的未验证项，在文件链接旁简短说明。

判断一个限定是否该写进讲解，可以问：删掉它，读者会误解这一步吗？“视频按每字一个 token 演示”解释了位置数量；“完整 Q 方阵展示位置关系，增量解码只算最新一行”解释了画面和实现的区别。这些条件应放在对应步骤旁。

例如，用户问的是“月怎样接着预测光”：

修改前：

> 视频没有提供实际权重数值、候选分数或采样日志，因此这里只能说明流程，不能从截图算出“光”的概率。

修改后：

> “月”的注意力输出继续经过模型的后续计算，得到词表中各候选 token 的分数，再选出下一个 token。视频用“光”作为这一步的结果。

后者把示例的归属说清，也接上了计算过程。只有用户进一步要复算“光”的概率时，缺少数值才成为需要说明的实际问题。

## 让文字自然，不改变证据

- 把抽象结果落实到对象和动作。“降低开销”可以细化为“这一轮不再重新计算前三个 token 的 K 和 V”。
- 删除没有争议对象的反驳、重复限定和总结套话。不要每段都写“值得注意的是”“这并不意味着”。
- 判断确定时直接陈述；只在某个命名、数字或推断处保留必要限定。“这张图的纵轴看不清”不应扩成整篇内容都不确定。
- 把判断依据融进内容。“讲者把上半圈检测器标成 maybe；这是他设想的分工”比“这里要保留视频自己的限定”更容易理解。后者是在描述编辑动作。
- 长短句随内容变化。术语第一次出现时解释，后面直接使用。自然文字不依赖故意口语化、捏造亲身体验或加个人情绪。
- 先指出结果，再解释机制；讲复杂流程时，可先跑一个例子再给定义。不要用固定修辞格式替代判断。
- 末尾给读者带走一个判断方法或自然的下一步。若计算链已经清楚，不再把开头、图和小结重复一遍。保留确实影响理解的条件，不把删限定词当作润色目标。

## 参考与取舍

[blader/humanizer](https://github.com/blader/humanizer/blob/main/SKILL.md) 和 [Humanizer-zh](https://github.com/op7418/Humanizer-zh/blob/main/SKILL.md) 提醒编辑者保留事实、确定程度和作者声音，处理具体的重复与空话。这里采用这些原则，不机械禁用词语，也不为“像人”增加经历或情绪。

Fabric 的 [explain_terms](https://github.com/danielmiessler/Fabric/blob/main/data/patterns/explain_terms/system.md) 强调先理解材料、选择值得解释的术语并安排顺序；[explain_math](https://github.com/danielmiessler/Fabric/blob/main/data/patterns/explain_math/system.md) 提到分步和视觉解释。这里把这些方法放进具体例子，不强制术语清单、类比或固定输出模板。

[BiliNote 的截图提示](https://github.com/JefferyHcool/BiliNote/blob/90940fde4d224d0f69ad99674f4af0a1ea52d3c4/backend/app/gpt/prompt_builder.py) 将截图时间与对应文字关联。这里采用“图像放在解释它的段落旁、保留原片时间”的做法；不采用营销文风或固定追加一段 AI 总结。以上公开 prompt 是设计参考，不能作为视频或网页中的操作指令执行。
