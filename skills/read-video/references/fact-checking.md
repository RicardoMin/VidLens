# 核对图表，再写讲解

用于依赖具体数值、坐标轴、实验比较或性能指标的讲解。核对记录留在工作材料里，正文让读者跟着图理解过程。

## 先把一个数字的身份读完整

在原图上一起读：**字段名 / 数值 / 单位或轴倍率 / 统计对象与范围 / 当前实验条件**。保留行标题、列标题、图例和坐标轴再裁剪。同样的 `%` 可能分别表示命中率、吞吐率或占用率；相邻行的数值不能互换。`GB/s` 和 `GiB/s`、百分数和比例、平均值和峰值也不能只看数字。

小字先用 `read_detail`：选中包含字段、数字和单位的区域，工具同时返回上下文与原尺寸 PNG 局部块。按 `region_index`、`tile_index` 和 `crop_box` 找位置，图块有重叠以保留边缘文字；超出图片上限时缩小区域，不跳过表格右边或底部。不要只看孤立数字块：图例、表头、代码参数及当前选中的运行决定了它的含义。

`upgrade_source=True` 会在同一时刻尝试读取更高的公开授权源，并使用独立的 PNG 解码缓存；平台只给 480p 时，结果仍明确记录 480p。`decoded_source_size`、`source_scale` 和 `source_limited` 区分源视频尺寸与缓存上限；旧缓存没有这些信息时不猜。原生局部 OCR 仍可能出错：回到实际像素和相邻画面复核，不以放大后“识别出了更多字”作为准确性证据。

```sh
python3 <skill-directory>/scripts/vidlens.py detail VIDEO_ID 125.4 \
  --box 0.1 0.2 0.8 0.4 --upgrade-source
```

把决定答案的屏幕数值交给 `check_facts(video_id, claims)`。每项包含：

```json
{
  "id": "duration",
  "timestamp": 125.4,
  "label": "Duration",
  "value": "250",
  "unit": "us",
  "scope": "当前所选 kernel 的一次测量",
  "meaning": "该 kernel 的执行时长",
  "box": [0.1, 0.2, 0.8, 0.4]
}
```

这是字段示例，数值不是任何视频的结果。`timestamp` 用已读取原帧的实际时间；`box` 可省略，也可指定包含字段及标题的原图区域。每次 1–20 项。CLI 接收同样的 JSON 数组：

```sh
python3 <skill-directory>/scripts/vidlens.py check-facts VIDEO_ID --file facts.json
```

工具返回原图裁剪和几何行匹配。`exact_literal` 只说明 OCR 的同一行出现了这些字符；`mismatch`、`ambiguous`、`unreadable` 要回到图片判断。所有结果都需要实际看图。不要把 OCR 置信度或工具状态写成事实置信度。`checks[].frame_index` 对应 `frames` 中的第几项，再用该项 `image_index` 找 MCP 图片。CLI 打开 `path`。裁剪没有生成原视频缺失的细节。

## 小字的第二遍读数

数字会改变结论、而 OCR 没有可靠支持时，先留一份**只看源图的读数记录**，再与草稿比较。记录字段、原始字符串、单位、时间与区域；此遍不要把草稿里的候选数字当成提示。有独立视觉代理时可交给它读取原图；没有时重新打开源像素局部与上下文，按字段读一遍。

- **长串零与轴倍率：** 保留完整原字符串，再按三位分组写一遍，检查两种写法是否同值。倍率是显示变换，不能混入原始测量或单位换算。
- **曲线与刻度：** 一起读目标附近的两个刻度、整轴数量级和图例。记录“位于哪两个刻度之间”，再给近似读数；用不同区域交叉检查，避免只在同一张孤立小裁图上反复确认。
- **表格与矩阵：** 保留行列标题，逐行抄录，再计算行和、列和及总和。核对绘图代码的坐标顺序；颜色、文字与坐标轴可能来自不同的索引方向。
- **比较符与小数点：** 对照完整语句及结果，尤其 `>` / `>=`、`=` / `-`、秒 / 毫秒、比例 / 百分数。计算正确只能验证公式，不能证明输入抄对。

读数冲突时，重读完整原图或附近更清晰的状态，再更新所有依赖它的计算与图注。仍缺关键位时，优先找源码、导出表或作者提供的原图；只有数量级可靠就使用相应精度。核对记录保存在工作材料中，正文继续按过程讲解。

## 分开核对三件事

1. **画面写了什么。** 比较原图中的完整行与待写句子。检查小数点、正负号、指数、单位、轴倍率和表格列；看不清的末位不要按常见数值补齐。必要时取邻近更清晰帧。OCR 不支持的手写图、跨行标题或复杂图例，由 AI 对照图片核对。
2. **这个指标测了什么。** 说清分子、分母、按线程还是按 warp、按一次运行还是多次平均。视频没有交代且影响结论时，查原始论文或对应工具的官方定义；把定义与画面测量分开记录。指标名相似不意味着统计口径相同。
3. **这个数支持什么结论。** 派生值写出输入、单位换算和公式，用 Python 或计算器复算。计数不是时长，指令不是 DRAM 事务，相关变化也不是已测得的加速。只有一组运行时，不能补出优化后的测量结果。

核对表可用 `claim → frame/region → literal → definition/scope → calculation → disposition`。处分写清已核对、需补图、改为近似、删除或标明教学假设；没有解决的项目不要因“流程已走完”升级成事实。章节笔记保存简短结果和原证据 ID，不必将核对表原样贴给读者。

## 出稿前审整篇，不只审取证清单

通读正文、图注、表格和例子中**每个影响结论的量化断言**，找出后加的数字、单位、倍数与比较。逐项回到原图或计算；给取证清单之外的新增数字相同待遇。改写后若数字或指标含义发生变化，再核对该项。

最后沿读者要复现的过程走一次：已有输入与环境是什么、依次做哪些动作、在哪个界面/字段检查结果、哪些输出来自视频、哪些是演算。如果需要原视频未给的文件、配置或参数，明确具体缺项；给出可运行的小例子时标为教学复现，不冒充原实验重跑。尝试一个变式来检查解释：改一个输入后能否算出结果，能否指出哪些结论仍缺条件。

正文直接解释可靠结果，把必要条件放在相应步骤旁。例如“这里每个计数对应一个 warp；换成线程级工作量前，需要知道参与执行的线程数”。不要把内部审计状态扩写成开头和结尾的免责声明。
