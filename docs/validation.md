“逐字恢复”比较分页返回内容与已获取字幕／ASR原文，验证没有漏页或截断；它衡量传输完整性。讲解正确性另外通过实际阅读、画面核对与事实检查验证。

### 阅读质量带来的改动

- 神经网络课程的 ReLU 定义在结尾。全片阅读把它与开头的 sigmoid 示例连起来，避免把所有激活值都说成 0–1；图中 `maybe` 也保留了讲者对隐藏层特征的假设性质。
- Attention 中文字幕把 `12,288 × 12,288` 说成约 1,500 万。实际图像显示两个维度，计算结果是 150,994,944。笔记保留原文及画面引用，把这处数量级错误定位到具体段落。
- 按候选数量均分代表帧，容易被密集动画影响。改成按真实时间分桶、优先变化后的保持期后，结尾章取到了清晰的 ReLU 公式，mask 章取到了完整的负无穷及零权重矩阵。全部视觉候选仍可顺序查看。
- 长课滚动字幕常互相重叠。章节边界现在保留平台起点，跨界字幕完整返回，避免一个长章后接若干秒短章；相邻章出现同一条字幕是保留上下文的结果。

### 无字幕课程的转写

B站前 120 秒缓存音频做了 base、small，以及各自加术语提示的四组对照。更大的模型和词表都只改善了部分词，仍会误识别 Q/K/V、token 或中文术语，因此保留 base 默认值和模型选择。新增 `vocabulary`、`refresh` 后，独立副本上的真实转写验证了替换旧 ASR、更新来源版本、再次调用命中缓存的行为。词表作为识别提示保存，解释中的关键符号仍通过画面核对。

### 接口、图片和交互

离线回归共 **289 项通过**，Ruff 和 skill 校验通过，源码包与 wheel 构建成功；另在独立临时环境安装 wheel 与锁定依赖，从 site-packages 启动 MCP，完成章节计划和原文读取。真实 stdio MCP 进程返回了 13 个工具，完成 `read_video → read_section`，实际发送 4 张图片，图片索引与文字元数据对应。离线回归覆盖了单帧快闪、微小文字变化、媒体替换、图片编码失败、预算失败、长字幕分页、笔记失效和引用校验。

离线 HTML 支持逐步讲解与可调温度的 softmax 概率图。最终生成脚本通过 Node DOM 的导航、键盘、输入事件和数值计算检查。当前浏览器策略拒绝 `file://`，因此本轮未验收真实浏览器布局和窄屏排版。

### 复现全片读取

先通过 `inspect --intent summary` 获取材料。`--visual` 会允许下载媒体和运行 OCR；只测已有字幕分页时省略它。私有响应只能写入 `--home` 内的 `--artifacts` 路径。

```sh
.venv/bin/python benchmarks/evaluate_study.py --home .vidlens \
  --video-id youtube:aircAruvnKk --visual \
  --artifacts .vidlens/study-evaluation \
  --output benchmarks/results/study.json
```

本轮以证据读取和技术解释的实际缺口推进迭代。尚未完成跨产品同题盲评，表中的结果不用于排名。

## 文本

固定 3Blue1Brown 神经网络第一讲的 231 条人工中文字幕，全文为 4,842 个估计 token。五道开发题涵盖四个主题，包含两种关于激活函数取值范围的问法。两种预算分别为 2,500 和 4,000，每个问题各测一次新进程和三次常驻服务，产生 40 条记录。评测使用 SQLite 的临时副本，按标注语轨过滤。平时查看画面产生的 OCR 会保留在用户缓存中。

计数器使用 `o200k_base`，覆盖完整工具 JSON。工具声明、图像、模型推理与最终生成属于其他开销。常驻检索受益于索引复用；这次新进程在两种预算下分别测得约 192 ms 和 154 ms，耗时包含解释器和依赖加载。每种预算的新进程 p50 只有五个样本。开发题窗口命中使用 50% 交叠阈值，同时记录每个窗口实际覆盖率和文字锚点。

本轮还检查了混合语轨的一个失败案例。早期优化版本在插入 OCR 后移动了语音边界，仍能命中 ReLU 片段，却漏掉随后给出的函数定义。最终检索按模态、来源和语言独立分组。两种问法都取回了定义原句，固定字幕与混入两条 OCR 的检查都保留了预标注窗口。

另用一条 116 分钟的英文 GPT 编程课抽查。询问 attention 缩放时，首次结果以 1,114 个估计 token 定位到方差解释，但讲者随后才说明 softmax 如何趋向 one-hot。补读 78:00–78:38 再用 1,186 个估计 token 取得该条件。这个样例验证了何时需要展开上下文。[对应讲解](https://www.youtube.com/watch?v=kCc8FmEb1nY&t=4654)

## 画面与分页

视觉对照使用两个已经下载的真实片段和一个可重建的幻灯片样本，均关闭 OCR，每次使用新的帧缓存，然后立即读取同一区间。三例的 FFmpeg 调用均从 12 次降至 5 次，缓存 JPEG 从 24 张降至 4 张；热命中约 0.4 ms。预览策略改变后，两条真实片段各有一个分桶的入选时间变化约 0.67 秒。快闪内容仍可能落在采样点之间。另用真实 stdio MCP 读取一段静态视频，四个采样时间点均指向同一张成功解码的图片。

分页样例使用 600 条合成中英字幕和已经缓存的词表。优化前后第一页均返回 21 条、估计 1,475 tokens。长字幕的逐字符恢复、游标失效、部分转写范围、跨进程读取、片段复用及安装配置保留均由离线回归覆盖。
