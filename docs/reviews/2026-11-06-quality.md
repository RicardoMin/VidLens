# 中文转写与视觉导航：真实视频对照

本轮保留 **0.1.0**。新增可选的 Apple Silicon 转写后端，以及保留原始全集的精简视觉导航。两项材料层面的提升已有实测；相同问题、相同四张图预算下，最终讲解的核心准确性与可读性没有测出增益。

## 中文技术词

比较材料为 [KV Cache](https://www.bilibili.com/video/BV1SmrSBfEg6/?p=1) 的 473–628 秒，以及新获取的 [TCP 三次握手](https://www.bilibili.com/video/BV18h41187Ep/?p=1) 的 210–360 秒。测试前独立查看原图，冻结问题、事实检查点、图片预算和评分标准；TCP 画面有烧录字幕，因此可以核对局部术语。KV 没有硬字幕，本轮也没有人工核听音轨，不将它计成逐字准确率。

| TCP 条件 | 预先固定的术语锚点保留 |
|---|---:|
| 原 CPU Whisper base，无提示 | 5 / 14 |
| MLX large-v3-turbo，无提示 | 12 / 14 |
| MLX large-v3-turbo，有术语提示 | 11 / 14 |
| 最终 MLX + 语音检测，无提示 | **12 / 14** |

这是带来源时间窗的词语保留检查，不是 WER/CER。字幕里的 TCP、Sequence、确认号等在新转写中更稳定；SYN 和“全双工”仍有错误。提示词修复了一个 SYN，却把后面两处 TCP 变成 TCB，因此工作流改为先不加词表，发现具体问题后再试少量已观察词汇。三组均保留示例数字，没有数字准确率提升的证据。

KV 的一个实质改善在 544–550 秒：旧转写把追加 K 后的结果说成 Q，新转写保留 K，与紫色矩阵一致。局部 V 仍可能被识别成“微矩阵”，关键字母继续通过原图核对。

还试验了 Qwen3-ASR 0.6B。它对 token、“全双工”和句读有改善，但出现“缓存 K/V”漏成“只缓存 key”的问题，因此未集成到生产路径。其时间戳是 30 秒音频窗，按重叠窗口计算的词语分数会包含额外上下文，不能与 Whisper 短段结果直接排名。模型名或局部词分更高，不足以抵消关系错误。

公开指标：[base](../../benchmarks/results/quality-tcp-base.json)、[最终 MLX](../../benchmarks/results/quality-tcp-turbo-post-vad.json)、[提示词对照](../../benchmarks/results/quality-tcp-turbo-post-vad-prompt.json)。原始不利样本、模型输出和哈希清单均保存在私有 `.vidlens/quality-2026-11-06/asr/`。

### 实现与失败处理

- `asr-mlx` 是可选 extra；通用 CPU 默认值保持兼容。已安装 MLX 的 Apple Silicon 环境会在阅读计划中提供对应建议配置，skill 显式选择后端。
- 模型在独立 worker 中加载，权重只放私有缓存，下载绑定提交与摘要校验；MLX 依赖不进入普通安装。
- 增加 Silero 语音检测与原时间映射。真实静音试验中，原生 MLX 曾输出“点赞订阅”类假字幕；最终路径直接返回空结果。长停顿的时间回映射有行为测试。
- 后端、模型、语言和词表共同决定缓存身份；跨后端替换只更新相应语言与区间的 ASR，失败保留旧材料。

最终独立 worker 对 KV 的 155 秒缓存音频返回 67 段，全部时间落在原片 473–628 秒内，观测总耗时 4.549 秒；模型已缓存，不含下载。另通过正式 CLI 在隔离数据库副本中完成转写，第二次调用命中缓存。这里没有把暖模型、首次下载与整条阅读流程混成一个速度指标。

实现参考：[MLX Whisper](https://github.com/ml-explore/mlx-examples/blob/main/whisper/README.md)、[faster-whisper 的语音检测与时间映射](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py)、[Qwen3-ASR MLX](https://github.com/gabrimatic/qwen3-asr-mlx)。

## 视觉候选

原始逐帧变化索引保持完整，新层只生成导航视图。它先选稳定区间、局部变化峰值与短事件探针，再比较低清图像的局部块差异、细节和空白状态。每项保留原候选游标，可以返回完整序列。

| 视频 | 原始候选 → 导航状态 | 候选减少 | 构建导航耗时 |
|---|---:|---:|---:|
| KV Cache | 1,565 → 154 | 90.2% | 0.763s |
| TCP 三次握手 | 3,115 → 201 | 93.5% | 0.523s |
| 神经网络第一讲 | 4,964 → 689 | 86.1% | 10.025s |
| Attention | 6,713 → 764 | 88.6% | 20.845s |

这些耗时使用已缓存的 360p 整片与原始扫描，不含下载、OCR、ASR，也不含 AI 看图。导航数量减少不等于画面语义已读完。

开发中，全局平均像素差异曾把不同公式合并。改为更细的局部块比较后，代码变化、指针噪声中的单帧事件、坏缓存和源替换回归通过。短事件探针超过上限或选择器失败时，工具明确返回完整视图。续页必须沿返回的 `view` 使用相应游标。

此外试验了用像素细节与多样性选择每章首批四图。实际打开三组前后共 24 张图：TCP 新末图补上了第三次 ACK，Attention 新末图的矩阵更大、更容易读；KV 则用 K 的拼接图换掉了 Q 的拆行图，存在取舍。因此最终产品采用：**首批图片保持稳定时间覆盖，后续展开使用精简导航**。像素排序的四图策略保留在评测工具中作实验，没有替换默认代表图。

公开数据：[视觉导航与有利／不利观察](../../benchmarks/results/quality-visual-selection.json)。算法参考 [PySceneDetect 的自适应局部变化](https://github.com/Breakthrough/PySceneDetect/blob/main/scenedetect/detectors/adaptive_detector.py) 与 [内容差异度量](https://github.com/Breakthrough/PySceneDetect/blob/main/scenedetect/detectors/content_detector.py)，实现继续使用现有 FFmpeg 和 Pillow。

## 最终讲解有没有更好

两位独立作者分别使用旧材料和升级后的转写加实验图片，完成同样的两道题。两侧使用相同写作指南、相同范围和四张原图，不读取旧笔记或其他条件。评阅者在不知道条件映射时按冻结标准逐项评分，并实际打开全部 16 张图；评分后才解盲。这是独立 AI 评阅，不是人类用户研究。

| 问题 | 旧材料核心准确性 → 新材料 | 旧材料可读性 → 新材料 |
|---|---:|---:|
| 用“月”走完 KV Cache 下一轮 | 20/20 → 20/20 | 10/10 → 10/10 |
| 用视频序号走完 TCP 三次握手 | 20/20 → 20/20 | 10/10 → 10/10 |

本次样本的旧答案已能结合画面纠正转写错误，新答案没有提高这些评分。新数据减少了术语噪声与候选数量，但这两题尚不能证明最终讲解更准确、更好读。两侧均没有大段无关防御文字；TCP 两侧都未在四张图里取到最后的完整确认号画面，正文通过原文与算式正确接续。

逐项与解盲结果见 [讲解评测指标](../../benchmarks/results/quality-explanations.json)。原稿、匿名包、原始评阅和条件映射保留在私有实验目录，任何交付稿编辑都另存副本。

评阅过程也经过核对：初评把 544 秒的 K 四行误看成分开的三行加一行，扣了新版 KV 的一分。放大原图并逐行检查后确认正文正确，独立勘误撤销该扣分，四份总分均为 34/34。初评、图片哈希和勘误保留，公开指标同时记录初始分与更正分；这次也说明图像评分需要实际像素复核。

## 复现与后续

```sh
# Apple Silicon 可选后端；普通安装继续支持 CPU
python3 scripts/bootstrap.py --apple-asr

# 已获取的视频可选择后端转写
.venv/bin/python -m vidlens --home .vidlens transcribe VIDEO_ID \
  --start 210 --end 360 --language zh --backend mlx-whisper

# 导航与完整变化序列分别分页
.venv/bin/python -m vidlens --home .vidlens scan VIDEO_ID
.venv/bin/python -m vidlens --home .vidlens scan VIDEO_ID --view full

# 转写 JSON 使用原视频绝对时间，含 range/backend/model/segments
.venv/bin/python benchmarks/evaluate_quality.py \
  --reference benchmarks/quality-cases.json --case tcp_handshake \
  --transcript TRANSCRIPT.json --output .vidlens/quality-check.json

# 同区间同图片预算比较，图片留在私有目录
.venv/bin/python benchmarks/evaluate_visual_selection.py \
  --video-id bilibili:BV18h41187Ep:p1 --start 210 --end 360 \
  --artifacts .vidlens/visual-check --output .vidlens/visual-check.json
```

公开参照是冻结检查表中术语部分的裁剪，保留原表哈希；不包含整段转写或视频图片。评分器修复了把 Sync 当成 SYN 的子串误判，并显式记录时间粒度，防止宽窗结果被当成更精确的识别。

完整离线回归 **368 项通过**，Ruff 与 skill 校验通过。另将 wheel 安装到独立临时环境，在项目目录外通过隔离 Python 启动 stdio MCP：13 个工具正常注册，读取 67 段缓存 MLX 转写，分别返回 154 个导航候选和 1,565 个原始候选；章节读取实际发送 4 张图片，图片索引与原始候选映射通过核对。安装后的 22 个源码模块与工作区一致，wheel 和源码包均未包含视频、模型、本机配置或运行缓存。

后续优先扩大人工标注的中文技术集，加入模型读不懂的困难题；视觉侧应评估问题与屏幕文字的相关性，而非继续单靠像素密度。Qwen 更大模型与强制对齐也需要以关键关系、时间归属和实际费用共同验收。
