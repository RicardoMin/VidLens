# 从视频阅读到完整技术讲解

本轮交付：[YOLOv1 精读：一张图片，怎样变成一组检测框？](../../examples/yolov1/README.md)。原视频为 [BV1KT2yBJESn](https://www.bilibili.com/video/BV1KT2yBJESn/?p=1)，39 分 27 秒。文章证据只通过 VidLens 获得，没有加入外部论文或网页事实。AI 编写解释、教学演算和 SVG；VidLens 保存知识结构、审核覆盖并导出成稿。

## 已落地的改动

| 阅读中的问题 | 本轮行为 |
|---|---|
| 连续 ASR 缺标点，章节容易退化为固定时长 | 用讲解转折和局部词汇变化生成候选边界；算法升级保留已有笔记／人工章节，不破坏引用。 |
| 检索片段无法组织一篇完整课程 | 新增持久化知识单元，可跨章引用，标记概念、机制、例子、推导、实验和局限，维护前置依赖。 |
| 检索命中结论却漏掉理解它的前提 | 主题与角色检索带回完整前置组；预算不足时明确省略整组。当前为词项检索，未引入向量库。 |
| 读过很多证据，正文依然只有几点结论 | 先保存文章计划，再检查核心知识、前置内容、计划中的每幅图与练习是否进入对应章节。来源／知识变化会使计划失效。 |
| 工具 JSON 比原文更占上下文 | compact 合并重复来源和相邻短句，保留每条原始 ID、偏移与完整文字；分页依据实际序列化结果控制。 |
| 图和代码散落在缓存，难以审稿 | 导出相对图片路径、真实目录锚点、HTML 预览、教学附件和哈希清单；来源图必须绑定本视频的注册帧。 |
| 不能区分下载、阅读与模型耗时 | 本地 metrics 记录操作耗时、文本估算及图片尺寸；失败计量不会遮蔽原错误。 |

分类与说明由读过证据的 AI 写入。程序校验引用、依赖、版本和正文落点，尚不判定某句话是否正确解释了来源。模型仍须完整阅读相关原文和画面。

## 这篇文章怎样生成

1. 通过项目重新读完六个已保留章节的 compact 原文，共 596 条转写、9,067 个字符。六章是已有笔记的布局；新算法在只读副本上提出 11 个候选章节，未替换原布局，也未将候选数量当成质量成绩。
2. 从项目取回损失、训练、速度、错误分析、组合实验、VOC2012 和艺术作品人物检测画面，实际打开源像素与局部裁剪。原始语音转写来自此前的 MLX Whisper large-v3-turbo 缓存。本轮是缓存重读，未重测平台首次获取或 ASR。
3. 保存 19 个核心知识单元及前置关系，组织为 10 节。使用同一组坐标连接网格分配、输出解码与训练责任；另用教学候选展开 NMS。虚构数值均明确标为教学演算。
4. 独立复核者先只看来源建立读数记录，再对照文章。补齐学习率的 75／30／30 阶段、数据增强上限、训练数据划分，以及每类 top N 后跨类别平均的饼图分母。
5. 通过 `article` 导出 5 张 SVG、3 张原图裁剪和 `calculations.py`。检查导出目录和图片，运行复算脚本，实际查看桌面及窄屏预览。

正文区分训练目标与推理预测、候选框与最终结果、AP 与 mAP、定位错误与背景误报、不同实验表格的基线。视频没有展开有目标格子中落选预测器的无目标置信度掩码，文章在相关位置保留这一具体缺口，没有补写成讲者已给出的规则。

## 验证结果

**原文传输。** 同一份缓存、6,000 token 分页预算下，verbose 为 10 页／54,041 估算 tokens，compact 为 4 页／18,058，减少 66.58%。逐字重组原文与原始证据 ID 均相同。此对照不含图片、工具声明、模型推理、输出文章或客户端历史，也不是总任务的成本降幅。执行器与原始汇总：[evaluate_compact_reading.py](../../benchmarks/evaluate_compact_reading.py)、[compact-reading.json](../../benchmarks/results/compact-reading.json)。

**来源核对。** `check_facts` 的六项自动检查返回五项歧义、一项不可读：`YOLO` 同时匹配 `Fast YOLO`，长段落、多表格及小数字仍会干扰行匹配。未把这些结果当作自动验真通过；实际查看返回的原图与独立裁图，核对 63.4 mAP／45 FPS、0.0005、71.8→75.0 以及 VOC2012 的 57.9。OCR 和视觉独立审核的状态分别保留。

**读者复算。** 先冻结五组参考答案，再给没有来源与作者上下文的 AI 读者仅提供文章及新输入：5×5／4 框／3 类输出，非正方形坐标空间，新的 IoU 与类别概率，新的 NMS 框和两个阈值，以及四种指标混用。五组答案均与参考一致，读者能区分训练 confidence 目标与实际预测值。结果见 [yolov1-article.json](../../benchmarks/results/yolov1-article.json)。这是单篇文章的可解题验收；没有旧稿或无文章对照，模型也可能具有相关先验，不能据此估计人类学习增益。

**软件与安装。** 544 项离线测试、Ruff、skill 校验、`git diff --check` 和离线锁文件检查通过。临时构建 wheel/sdist，从项目外的独立环境安装并实际启动 stdio MCP，验证默认 19／扩展 24 工具、compact 原始引用、知识保存检索、计划审核、文章导出及 metrics。安装的 30 个运行时 Python 文件与当前源码一致，归档未包含私有缓存、模型和凭据。版本仍为 0.1.0。

**排版。** 浏览器实测 1280 像素与 390 像素视口，图片全部加载，窄屏无整页横向溢出，目录跳转有效；五张教学图逐张检查，三张源图实际查看。修复了中文标点包在粗体末尾导致字面 `**` 的展示问题。窄屏阅读复杂图仍适合放大图片。

## 下一步有价值的工作

- 为长课程的知识目录增加游标与全量导出，减少依赖提高预算或拆查询。
- 改善图表字段精确匹配，尤其是模型名称互为子串、多栏段落和细小小数；保留原图复核路径。
- 扩大文章级盲评，加入旧稿、无文章对照与真正的新手读者；分别统计事实遗漏、推导错误和复现失败，避免单个总分掩盖问题。
- 将每次阅读、图片补取、草稿修订和导出绑定同一个 run ID。当前部分图像工具调用经过会话中已启动的旧 MCP 进程，没有并入新计量，不报告整篇任务的端到端耗时或实际 token 账单。
