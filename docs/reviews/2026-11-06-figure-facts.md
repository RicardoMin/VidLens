# 图表事实核对与读者复现

本轮保持 **0.1.0**，重点是数字、单位、指标含义与推导。新增 `check_facts`，配合原图裁剪、指标定义和出稿前全文审计。服务不调用额外托管模型。

## 为什么需要这一步

上一轮 CUDA 讲解把 L1/TEX 的 96.11% 写成约 93%，却在预设量表内拿到满分：这句额外断言没有进入评分项目。数值是否出现过、是否属于正确字段、解释是否符合指标定义，是三个不同问题。

现在的工作流是：

```text
原文与原图 → 待核对的数字、单位、指标和范围
                       ↓
           按 OCR 位置关联同一行 + 原图裁剪
                       ↓
          AI 看图 → 核对定义 → 带单位复算
                       ↓
           审全文新增断言 → 图文讲解
                       ↓
              独立读者判断与运行代码
```

## 实现与边界

- **保留位置。** Vision 逐行框、Tesseract 逐词框统一为左上角归一化坐标。旧 OCR 文本兼容；布局缓存版本为 2，升级失败保留旧文字。普通取帧不展开位置数据，核对时只返回有关的行。
- **绑定字段。** `check_facts(video_id, claims)` 接收字段、数值、单位、统计范围、解释与原帧时间，可指定包含表头的裁剪。数值和单位分别比较；跨行数字、重复标签、多数值列分别报告不匹配或歧义。`scope`、`meaning` 是待核对陈述，不能靠填写它们获得认证。
- **保留原像素。** 裁剪缓存和 MCP 图片采用 PNG；同一原帧的不同区域拥有独立图片索引。相同像素在不同时间复用缓存时保留各自引用时间。图像摘要和来源版本跟随结果，编码后再检查来源变化。
- **审整篇。** [技能流程](../../skills/read-video/references/fact-checking.md)要求 AI 看字段、单位、统计对象和实验条件，必要时查官方定义，再复算派生值。出稿时审正文、表格、图注和例子中新加的量化断言。内部核对记录不变成正文里的大段免责声明。

`exact_literal` 仅表示 OCR 字面一致；指标含义、图例关系、实验归属仍需看图和判断。坐标图、手写公式、跨行字段及仅在表头给出的单位不由行匹配器强行解释。

实际测试也暴露了局限：可读的合成表格中，Vision 给识别出的文字全部标了 1.0 置信度，却漏掉两个百分号。新工具将“数字正确但单位缺失”保留为未读清；不会用置信度替代事实核对。

本轮真实 480p NCU 小字，15 项候选在本机 OCR 复核后仍均为 `unreadable`；作者通过实际看裁剪与官方定义完成核对。另在上一轮开发画面上尝试 2×、3×、4× 插值放大，虽然识别出了更多文字，却出现错字和错误数字，没有作为自动补值方案上线。工具能组织证据，不能恢复原视频缺失的细节。

## 更有区分度的评测

使用[同一中文 NCU 教程](https://www.bilibili.com/video/BV1nkgN6LE7h/?p=1)此前未评估的两个范围：

| 案例 | 范围 | 核心考察 |
|---|---|---|
| Scheduler Statistics | 15:36–18:02 | 硬件／理论／实际驻留量，Eligible 与 Issued 的区别，平均数和周期百分比的分母 |
| Warp State 与 Instruction Statistics | 18:02–20:05 | 指令次数与周期，warp 与线程口径，队列等待与数据依赖，指令计数能否推算流量 |

两位独立作者使用相同 7 张原图、相同原始 MLX 转写、相同问题及长度要求，都可以裁剪、计算和查官方定义。对照使用上一轮写作指南；新流程增加结构化事实表、`check_facts` 和全文核验。新流程原始候选、OCR 失败与后续更正均保留。

问题、12＋10 项必需事实、参考、读者题和原图摘要先冻结；作者完成后冻结原稿。匿名评阅者逐项看图、核对必需事实，再检查全文额外断言。`benchmarks/evaluate_fact_review.py` 校验每个数字位置是否有对应判断，包括代码、公式、单位指数和图注；允许有理由地排除字段编号和引用时间。该脚本检查覆盖与出处，不代替语义评阅。

读者只接收对应两篇讲解及其配图，完成六题：源图字段重建、改条件后的诊断、调度器短程序、warp 计数到标量 FLOPs 的换算，以及按栏目重建诊断流程。原始代码不修改，实际运行冻结输入、冻结变体和额外变体。日志绑定 case、题号、读者文件和代码摘要；借用别人的成功日志或用简单输入替换冻结变体会被拒绝。

另设一名只看题目的 AI 读者，区分材料提供的信息和题目条件／模型已有知识。这里验证的是 AI 读者与教学程序；没有在 NVIDIA GPU 上复跑原 kernel，也不是人类学习效果研究。

## 结果：关键误解是否传给了读者

| 检查项 | 上一轮流程 | 本轮核对流程 |
|---|---:|---:|
| Scheduler 必需事实 | 12 项正确 | 12 项正确 |
| Instruction 必需事实 | 9 项正确、1 项遗漏 | 9 项正确、1 项遗漏 |
| 额外关键语义错误的独立根因 | 1 个，正文出现 3 次 | 0 个 |
| 独立读者任务 | 5 题通过、1 题失败 | 6 题通过 |
| 教学代码与冻结变体 | 通过 | 通过 |

有意义的差异是 **`lg_throttle` 的含义**。旧流程稿把本地／全局内存指令队列已满的等待，讲成 L1TEX 数据依赖等待，并在三个位置沿用；这是一个根因，不能当成三个独立失败来放大收益。旧稿读者随后在诊断复现题中重复这个错误，导致该题失败。新流程作者保留了初读的候选误解，在实际检查裁剪与官方定义后改正；对应读者正确说明了等待类别。

两套稿子的主要数值和单位均正确，Scheduler 三题也都通过，本次没有测出这些部分的增益。两篇 Instruction 原稿还共同漏掉了明确比较“同一个 warp 约 29.3 周期／指令”和“scheduler 约 3.7 周期／发射”的跨节说明；读者可以从配套 Scheduler 稿补足。交付样例另补了这张对比表，原始稿和评阅结果保持冻结，未追溯改分。

只看题目的对照为 **3 题通过、3 题部分完成**，两道程序题也能通过。因此程序运行正确不能单独证明讲解带来了学习增益；本轮更明确的证据是，错误的指标解释是否进入了读者的后续判断。该结果来自一次 AI 对照，不能据此推广到所有视频或人类学习者。

新旧两组实际图像查看次数分别为 19 与 17（含重复查看），提示长度及核对成本未配平；没有测量模型账单。公开逐项记录见 [figure-facts.json](../../benchmarks/results/figure-facts.json)，问题范围见 [fact-cases.json](../../benchmarks/fact-cases.json)。

## 本轮修复

| 问题 | 处理 |
|---|---|
| 纯文本 OCR 按列输出，字段与数值失去对应位置 | 保留框位置，按几何行核对，歧义留待看图 |
| 上标 `10³` 被 NFKC 变成 `103` | 保留上／下标，仅折叠等价全角 ASCII；单位 `m²` 也不变成 `m2` |
| 同帧不同裁剪共用图片索引 | 索引加入实际裁剪区域 |
| 相同图像缓存复用旧引用时间 | 返回当前调用的原帧时间 |
| 裁剪反复 JPEG 压缩 | 裁剪缓存与 MCP 采用 PNG |
| 全文额外数字漏评 | 数字位置清点与逐断言关联，另审无数字的语义结论 |
| URL 后的中文句子被整体排除 | 修复裸 URL 和自动链接的结束边界 |
| 成功运行日志误归属、掩盖失败或漏跑变体 | 绑定读者／题目／case，检查逐项结果及冻结输入覆盖 |

## 复现

```sh
.venv/bin/python -m vidlens --home .vidlens check-facts VIDEO_ID --file claims.json

.venv/bin/python benchmarks/evaluate_fact_review.py --inventory answer.md
.venv/bin/python benchmarks/evaluate_fact_review.py \
  --reference hidden-reference.json --questions reader-questions.json \
  --review review.json --require-execution SR2 --require-execution IR2 \
  --output result.json
```

原视频、原图、转写、作者原稿、核对表、匿名版本和执行日志位于私有 `.vidlens/fact-check-2026-11-06/`，由 `.gitignore` 排除。公开指标只保留结果与出处摘要。更新后重连 MCP，才能发现新工具；CLI 可直接使用当前项目环境。

## 验证完成情况

完整离线回归 **454 项通过**，Ruff、skill 格式检查和文档链接检查通过。项目 skill 已同步。独立 core-only 安装环境从项目外启动真实 stdio MCP，发现 14 个工具，`check_facts` 成功交付同一原帧的两张不同 PNG 裁剪，图片索引正确，完整原帧交付数保持为零；沙箱内 Vision 不可用时返回 `unreadable` 和实际图片，不冒充字面核对通过。

安装后的 Python 模块与当前源码逐字比较；源码包和 wheel 排除运行缓存、模型、媒体及本机配置。没有提交或推送。

指标含义核对使用 [NVIDIA Profiling Guide](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html)，特别是 SchedulerStats、WarpStateStats、每 opcode 计数与 warp stall 定义。官方定义解释统计口径，视频原图提供这一次运行的观测值。
